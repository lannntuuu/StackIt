## 0. 脏数据勘察（设计地基）

| 事实 | 例子 | 设计含义 |
|---|---|---|
| 周表**倒序**，标题**无年份** | 行 32 `09-07~09-13` → 行 3694 `12-25~12-31` | 先 reverse，再靠"月份上跳=跨年"推断（§4.2 D） |

| 一格多条 + 时间格式混杂 | `16.15 B2 2 B6 2 复合2`、`16..07`、`24.00` | 按时间锚点切段，一条正则全覆盖 |

| **时间与品名粘死无空格** | `16.50 A 17.06E` | 切分须保留时间后紧跟的字母 |
| 剂量后缀含错字；有无时间的裸记录 | `2片` `2篇` `两边`；`鱼油1` | 容忍错字；裸记录落 `precision:'day'` |

| 周表缺失；标题写错 | `03-15`→`03-02`；`08-31~08-05` | streak 处理空洞；以"起始日+行槽位"为准 |
| **列头会污染关键词统计** | `维生素C` 128 次**全在表头**，数据行 0 次 | 校验报告必须排除表头（§4.3） |

## 1. 技术选型

**推荐：纯前端静态 PWA = Vite + React + TypeScript + Dexie(IndexedDB) + 手写 SVG + 原生 CSS**

**存储形态**：纯前端 PWA + IndexedDB（Dexie），唯一真值是可导出的 JSON 文件，IndexedDB 只当工作副本 —— 它会被清缓存、隐私模式、iOS Safari 7 天策略抹掉，不是长期存储。

| 层 | 选择 | 理由 |
|---|---|---|
| 存储 | **IndexedDB** | 移动端唯一支持结构化 + 索引 + 大容量 |
| 构建 | **Vite** | TS 与 PWA 插件必需，产物为静态文件 |
| 框架 | **React + TS** | 筛选状态多；TS 是防"不确定时间被当精确值用"的防线 |
| 图表 | **手写 SVG**（约 200 行） | 只需热力日历/柱状/时段/甘特四类，Recharts 多 400KB 且卡 |
| 样式 | 原生 CSS 变量 | 无构建负担 |

| 否决方案 | 理由 |
|---|---|
| 带后端 | 部署/备份/鉴权/费用 = 运维负担，与"零运维"冲突；唯一收益多端同步，导出 JSON 即覆盖 |
| localStorage | 5–10MB 上限、无索引、只存字符串；现约 300KB 三年后必超限，仅可存配置 |
| 原生 JS | 5+ 联动筛选器手写 DOM diff 会失控，且丢掉 TS 类型保护 |
| Svelte / Vue | 非不能用，但复杂点全在派生状态与图表生态，React+TS 最成熟 |
| 无构建单 HTML | 失去 TS；`precision` 被误用则统计结论直接错 |

## 2. 数据模型

**核心原则**：日期**默认确定**（年份问题已解决），只有"时刻"可能缺失；外用与口服剂量语义不同，须按 `route` 分流。

```ts
/**
 * 时间点。v2：date 恒为绝对日期（年份已由周一起始约束确定），
 * 不确定性只体现在「时刻缺失」与「极少数日期需修正」两处。
 */
interface When {
  date: string;                 // 'YYYY-MM-DD' —— 绝对日期，恒有值
  time: string | null;          // 'HH:mm' | null —— null = 只知是哪天
  precision: 'minute' | 'day';  // 有 time 即 minute，否则 day（'week' 已废止）
  /** 日期置信度：绝大多数为 'exact' */
  dateConfidence: 'exact' | 'inferred';
  /** 仅 inferred 时给出说明，如 'week-start +1d off-by-one 修正' */
  dateNote?: string;
  raw: string;                  // 永不丢失的原始文本，如 "16.15 B2 2 B6 2 复合2"
}

type Route = 'oral' | 'topical';   // 口服 / 外用
type Group = 'B族'|'维C'|'脂溶性'|'矿物质'|'脂肪酸'|'外用'|'其他';

/** 品类枚举（由实际数据词汇导出，非凭空设计） */
type ItemId =
  | 'b1' | 'b2' | 'b6' | 'bComplex'      // B族：B1/B2/B6/复合
  | 'vitC' | 'vitE' | 'vitA' | 'vitD3'   // 维生素：C/E/A/D3
  | 'zinc' | 'calciumD3K2' | 'magnesium' // 矿物质：锌/钙d3k2/镁
  | 'fishOil' | 'ps'                     // 脂肪酸/其他：鱼油/PS
  | 'minoxidil' | 'seleniumSulfide';     // 外用：米诺地尔/二硫化硒

interface Item {
  id: ItemId;
  name: string;                 // '维生素E'
  /** 只增不删，保留历史写法；含单字母与粘连写法 */
  aliases: string[];            // vitA: ['A']; vitE: ['E']; bComplex: ['复合','复合2','复合维生素','复合维生素2']
  route: Route;                 // 外用剂量语义是"次/部位"，与口服"片数"不可比
  group: Group;
  defaultDose?: number;
  doseUnit: string;             // '片'|'粒'|'次'|'ml'
  /** 启用/停用时间段；空 = 视为全期启用 */
  activeWindows: Array<{ from: string; to: string | null; note?: string }>;
  archived: boolean;
}

interface IntakeEvent {
  id: string;
  itemId: ItemId;
  when: When;
  dose: number | null;          // null = 只记了时间没记剂量
  slot: '早' | '中' | '晚' | null;   // 取自行标签，不从时间反推
  source: { sectionRaw: string; weekday: string; line: number; colHeader: string };
  confirmed: boolean;           // 人工确认过；未确认的可在统计中排除
  note?: string;
}

type ObsKind = 'symptom'|'benefit'|'sideEffect'|'lab'|'note';

/** 与服用事件平级 —— "好转"是时间跨度，不是某个事件的属性 */
interface Observation {
  id: string;
  kind: ObsKind;
  subject: string;              // '舌尖溃疡' | '脱发'
  severity: number;             // 0–5，趋势图靠它
  when: When;
  /** 用户主观标注的线索，仅用于时间轴叠加，不作结论 */
  suspectedItemIds?: string[];
  text?: string;
}
```

## 3. 统计口径

> **v2 前提变更**：年份已确定 ⇒ **所有事件都有绝对日期，统计默认使用全量 1488 条**。
> 仅两类需降级处理：① `precision:'day'`（无时刻，约 6%）—— 影响小时直方图与时段分布，不影响按天/周/月的统计；② 3 个 off-by-one 周（约 25 条）—— 日期已修正，仅在"日期修正清单"里留档，不参与降级。
> 因此**统计口径不再需要 `dateConfidence` 过滤分支**，比 v1 干净。

### 3.1 依从性（难点：原始数据没有"计划"）

**三层，默认只展示 L1。**

**L1 观测型**（不假设计划，永远可算）：覆盖天占比 = 有记录天数 ÷ 期内自然天数；记录强度 = 事件总数 ÷ 有记录天数；**中位间隔** = 相邻事件日期差的中位数（比"率"更反映真实节奏）。

按"相邻事件间隔 ≤14 天视为连续，>14 天切一刀"切出持续服用期：

```
期望周频次 F = 期内各周事件数的中位数（用户手填优先于推断）
周依从性  A_w = min(实际周事件数 / F, 1.0)     // 截断，超量不算超额完成
期依从性  A   = mean(A_w)，覆盖期内所有周（含 0 次的周）
```

**分母 = 期内的周数**，不是天数也不是计划次数：原数据本身是周表，用户心理单位是"周"，且周粒度能吸收"某天忘、周末补"的噪声。基线来源须显式标注：`基线=推断（中位 3.0 次/周）` 灰字 vs `基线=你设定的 3 次/周` 正常色，**绝不能把推断值伪装成"你的计划"**。

**L3 连续坚持**：日 streak（连续每天有记录）用于高频品类，周 streak（连续 `A_w ≥ 0.8`）用于低频；默认按目标频次自动选。**缺失的周表视为断链**——无法区分"吃了没记"和"没吃"。

### 3.2 时段分布
**槽位分布**（早/中/晚）直接用行标签，**不**从时间反推 —— 数据里 `16:15` 记在"中"行，说明用户的"中"比常识宽。**小时直方图**只用 `precision==='minute'` 样本并标注 `n=xxx`（约 94% 有时间）。

> 注：**E / A 几乎全在"早"行**（`10.54 E A`），若把两个单字母误并成"EA"一个品类，不仅品类错，还会让 E/A 的时段与依从性统计全错。

### 3.3 趋势
周桶（ISO 周）/ 月桶，指标为事件数、覆盖天占比、平均剂量。**缺失周画成断点而非 0**，避免"没记录"被读成"没吃"。

### 3.4 品类生命周期
用甘特条呈现（一条时间轴，每品类一条，分段着色）：

```
firstSeen / lastSeen = 最早/最晚事件日期
gap > 30 天          → 切为多个"服用期"
status: 'active'(距今≤14天) | 'lapsed'(≤60天) | 'stopped'(>60天)
duration = Σ 各期(end-start)   // 不是 lastSeen - firstSeen
```

### 3.5 效果关联 —— **只做"同期观察"，不做相关性检验**

呈现（单个观察条目详情）：上方 `subject` 严重度折线 → 中部叠加品类服用甘特条 → 下方**前后窗口对比表**

| 指标 | 观察前 14 天 | 观察后 14 天 |
|---|---|---|
| 品类 X 覆盖天占比 | 40% | 85% |
| 品类 X 周均次数 | 1.2 | 3.0 |
| 症状严重度均值 | 3.0 | 1.5 |

**防误读硬约束（写成组件级断言，不是文档约定 —— 文档会被忘，组件不会）：**

1. 标题固定为「同期观察」，**禁用**"导致/因为/有效/见效/改善率"
2. 常驻灰字：`仅表示时间先后，样本 n=1，无法区分效果、自然病程与安慰剂`
3. **不输出相关系数 / p 值 / 置信区间** —— 给数字会让人误以为做过检验
4. 前后窗口样本 <5 条时**不渲染**对比表，改显示"样本不足，仅供备忘"
5. 提供"这条我确认过"手动标记，把主观判断显式化

## 4. 导入器设计

### 4.1 产出物：**先生成待确认中间文件，人工过一遍再入库**

v2 调整：年份已确定，需人工裁决的范围**大幅收窄**为「品类归并 + 少量错字」，不再是「年份 + 品类 + 错字」三座大山。但**仍保留 staging 环节**，因为 `复合`/`复合2`/`复合维生素` 是否同一物只有用户知道，错字也无法 100% 自动归位。

```
记录.md → parse → normalize → resolve →【staging.json + report.html】→ 人工修订 → commit → IndexedDB
```

`staging.json` 人可读可编辑；重跑时靠 `line + raw` 保留已确认状态，**修一次永久有效**。

### 4.2 解析策略

**A. 按表头名映射（不按列位）**，并跳过混入数据行的伪表头。

> **列头排除是硬要求**：`维生素C` 在文件里出现 128 次，**全部在表头，数据行 0 次**。任何基于关键词的校验若不排除表头，数字会虚高 100%。判定规则：星期列 ∈ 周一…周天/周日，或（星期列为空 且 槽位列 ∈ 早/中/晚）⇒ 数据行；否则视作表头/分隔/总结行，跳过。

```ts
const HEADER_ALIAS: Record<string, string> = {
  '维生素C':'vitC', '维C':'vitC',
  '维生素B复合':'bComplex', 'B复合':'bComplex',
  '其他维生素':'other', '其它维生素':'other',   // 两种写法都要
  '锌':'zinc', '米诺地尔':'minoxidil', '二硫化硒':'selenium',
};
// 每个 section 独立解析自己的表头 → colIndex → itemKey
// 数据行若命中 HEADER_ALIAS 的键（伪表头行）→ 跳过
```

**A2. 品名字典（含单字母 E / A）**

实测数据单元格里的全部非时间、非剂量 token 共 19 种：`B6(165) B2(104) 复合2(68) B1(66) D3(43) A(37) E(37) 鱼油(10) 复合(6) 鱼油1(6) 复合钙(5) 维生素D3(4) 镁(3) 两边(2) 钙d3k2(2) 复合维生素2(1) ps(1) 复合维生素(1)`。据此定字典（**最长匹配优先**，故 `复合维生素2` 必须排在 `复合` 前）：

```ts
const ITEM_DICT: Array<{ id: ItemId; match: string[]; group: Group; route: Route }> = [
  { id:'bComplex', match:['复合维生素2','复合维生素','复合钙','复合2','复合'], group:'B族',  route:'oral' },
  { id:'b1',       match:['B1','b1'],       group:'B族',    route:'oral' },
  { id:'b2',       match:['B2','b2'],       group:'B族',    route:'oral' },
  { id:'b6',       match:['B6','b6'],       group:'B族',    route:'oral' },
  { id:'vitC',     match:['维生素C','维C'], group:'维C',    route:'oral' },
  { id:'vitE',     match:['E','e','VE'],    group:'脂溶性', route:'oral' },  // 单字母，必须全词匹配
  { id:'vitA',     match:['A','a','VA'],    group:'脂溶性', route:'oral' },  // 与 E 相互独立
  { id:'vitD3',    match:['维生素D3','D3'], group:'脂溶性', route:'oral' },
  { id:'zinc',     match:['锌'],            group:'矿物质', route:'oral' },
  { id:'calciumD3K2', match:['钙d3k2','钙D3K2'], group:'矿物质', route:'oral' },
  { id:'magnesium',match:['镁'],            group:'矿物质', route:'oral' },
  { id:'fishOil',  match:['鱼油1','鱼油'],  group:'脂肪酸', route:'oral' },
  { id:'ps',       match:['ps','PS'],       group:'其他',   route:'oral' },
  { id:'minoxidil',match:['米诺地尔'],      group:'外用',   route:'topical' },
  { id:'seleniumSulfide', match:['二硫化硒'], group:'外用', route:'topical' },

```

> **`E` / `A` 的三条硬约束**（来自 `10.16 E 10.39 A` 及 `E A` 37 格实测）：
> 1. 它们是**两个独立品类**，不是"EA"。`E A` 一格须产出 2 条事件。
> 2. 必须**全词精确匹配**（`t === 'E'`），绝不能用 `includes('E')` —— 否则 `鱼油1` 之类会被误判。
> 3. 由于是单字母，**禁止任何"取首 token 为品名"的启发式**，必须走上面的全量字典匹配。

**B. 行 → (星期, 槽位)**：星期列非空则开启新的一天，空则沿用上一天；`总结` 行跳过。

**C. 复合单元格切分（核心）**：以时间 token 为锚点切段，段内字典贪心匹配 (item, dose)。注意**时间后可能紧跟品名且无空格**（`17.06E`），切分时须把紧跟的字母留在段内。)。
```ts
// 覆盖 15.10 / 15:10 / 9.55 / 09.28 / 16..07 / 24.00
const TIME_RE = /(\d{1,2})\s*[.:]{1,2}\s*(\d{1,2})/g;
// 剂量后缀（含错字 篇/边）
const DOSE_RE = /^(\d+)\s*(片|粒|颗|篇|边|次)?$/;

function splitSegments(raw: string) {
  const hits = [...raw.matchAll(TIME_RE)].map(m => ({
    hh:+m[1], mm:+m[2], start:m.index!, end:m.index! + m[0].length,
  }));
if (!hits.length) return [{ time: null, body: raw }];      // 无时间 → precision='day'
  return hits.map((h,i) => ({
    time: normalizeTime(h.hh, h.mm),                          // 24.00 → 次日 00:00；校验 0–23
    // 关键：段起点从"时间后紧跟的字母"之后开始（吃掉 17.06E 里的 E），
    // 并把该字母作为该段的首个品名候选
    ...peelGluedItem(raw, h),
    body: raw.slice(h.end, hits[i+1]?.start ?? raw.length),
  }));
}

/**
 * 处理时间与品名粘死：`16.50 A 17.06E` → 时间 17.06 后紧跟 'E'，中间无空格。
 * 用 (?=[A-Za-z]) 前瞻把字母识别为品名，并从 body 中剔除已消费部分。
 */
function peelGluedItem(raw: string, h: { end: number }) {
  const m = /^[A-Za-z]+/.exec(raw.slice(h.end));
  return m ? { gluedItem: m[0], end: h.end + m[0].length } : { gluedItem: null, end: h.end };
}

// 段内匹配：处理 `11.08 复合 B2 2 B6 2`（item 在剂量前）
//          与 `10.16 B6 2 10.43 B2 2`（时间夹在中间）
function parseSegment(body: string, dict: Dict): Parsed[] {
  const out: Parsed[] = []; let pending: string | null = null;
  for (const t of body.trim().split(/\s+/).filter(Boolean)) {
    const item = dict.matchLongest(t);            // 最长匹配：'复合维生素' 优先于 '复合'
    if (item) { if (pending) out.push({item:pending, dose:null}); pending = item; continue; }
    const d = DOSE_RE.exec(t);
    if (d && pending) { out.push({item:pending, dose:+d[1]}); pending = null; continue; }
    if (d && out.length) { out[out.length-1].dose = +d[1]; continue; }   // 补挂
    unknown.push(t);                              // → 进报告，人工裁决
  }
  if (pending) out.push({item:pending, dose:null});
  return out;
}
```
> 关键：`TIME_RE` 全局扫描而非只取行首，才能正确切 `14.30 B6 16.56 B1`；`peelGluedItem` 处理 `17.06E` 粘连；`复合2`/`鱼油1` 由字典最长匹配直接吸收（注册为独立 alias，无需特殊规则）。

**D. 年份确定（v2：不再是"推断"，是带校验的求解）**

用「**每张周表的起始日必须是周一**」作约束反推绝对年份：

```
1. reverse(sections)                      → 文件倒序还原为正序（旧→新）
2. 首个 section 年份锚定 = 2023（外部事实：今天 2026-09-07 周一，
   且最新一周恰为 09-07~09-13，反推最老周 = 2023-12-25）
3. 顺序遍历：当前月份 < 上一月份 → year++     （跨过 1 月 1 日；本数据跨界数 = 3）
4. 求解后校验：每 section 起始日 + 该年 → 是否为周一
5. 周内 7 天 = 起始日 + 星期 offset（用日期库算，跨月自然进位）
```

**实测结果（已复核，作为回归基线）**：

- 周数 `2023:1 / 2024:44 / 2025:51 / 2026:31`；事件数 `25 / 358 / 728 / 377`（合计 1488）
- **127 周中 124 周起始日准确落在周一**；其余候选年份方案错误率 63%~100%，故此解唯一
- 旁证：最新周 `09-07` = 2026-09-07 周一，与"今天"一致

**3 个例外（off-by-one 笔误，已定位并修正）**：

| 行号 | 原标题 | 原起始日 | 星期 | 修正后 | 星期 |
|---|---|---|---|---|---|
| 1747 | `06-15~06-21` | 06-15 | Sunday | **06-16** | Monday ✓ |
| 1776 | `06-08~06-14` | 06-08 | Sunday | **06-09** | Monday ✓ |
| 1805 | `06-01~06-07` | 06-01 | Sunday | **06-02** | Monday ✓ |

这 3 周**连续相邻**，且修正后与前后邻周（`05-26` / `06-23`，本身即为周一）**完全衔接无空洞**，可确认是同一段的一处 +1 天笔误，而非年份错配。处理：起始日 +1 天后正常解析，事件标 `dateConfidence:'inferred'` + `dateNote:'week-start +1d off-by-one 修正'`，并在报告的「日期修正清单」列出。**`raw` 仍保留原文本，可随时回滚**。

> 结论：**默认 `dateConfidence:'exact'`，全量数据直接参与统计**，不需要 v1 的大面积降级分支。

**E. 写入 When**：有时间且合法 → `precision:'minute'`；有时间但非法（如 `25.70`）→ `day`+告警；无时间（如 `鱼油1`）→ `day`。`dateConfidence` 默认 `exact`，仅上述 3 周为 `inferred`。

### 4.3 校验与报告

导入必须输出 `report.html`。**前置规则：所有按品类/关键词的统计必须先剔除表头行**，否则 `维生素C` 之类会把数字虚高 100%（实测 128 次全在表头、数据行 0 次）。

| 检查项 | 通过标准 |
|---|---|
| 总量对账 | 事件数 ≈ 1488 ±5%（**排除表头后**统计） |
| 按年分布 | 对照基线 `25/358/728/377`，偏差 >5% = 年份求解有问题 |
| **周一校验** | 必须 ≥124/127（97%）；未命中逐个列出并进「日期修正清单」 |
| 日期修正清单 | 必须且仅含 3 周（行 1747/1776/1805），+1 天后衔接无空洞 |
| **E/A 计数** | E=37、A=37、共 74 条事件，全部落在「其他维生素」列；**若 E+A ≠ 74 或出现在别的列 = 字典/匹配有误** |
| 按品类分布 | 对照实测词频 `B6:165 B2:104 复合2:68 B1:66 D3:43 A:37 E:37 …`；`first>last` 或空 = 错误 |
| 时间合法性 | 时 0–23 分 0–59；`24.00`/`16..07` 须进"已修复"清单 |
| **粘合 token** | `17.06E` 须被识别为 1 条 E 事件（不是 0 条也不是 2 条） |
| unknown token 清单 | 出现次数 + 逐条裁决（加 alias 或忽略） |
| 跨列头一致性 | `其他/其它维生素` 须合并到同一 key |
| **抽样对照** | 随机 20 条：原文行 → 解析结果并排（最有效的信心来源） |
| 置信度分布 | `day` 占比应 ≈6%；`inferred` 日期应 ≤25 条；超出即解析有问题 |

顶部总览：`127 周 / 1488 事件 / 15 品类 / 未识别 N token / 日期修正 3 周`。
