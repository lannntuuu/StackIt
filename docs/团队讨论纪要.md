## 0. 主持独立核验（最高置信度结论，优先于任何成员报告）

这几条是主持自己跑出来的，且**已被代码验证**，优于各方报告中的估计值。

### 0.1 年份已破解：2023-12-25 ~ 2026-09-07

数据最大的坑是标题只有 `MM-DD` 没有年份。主持用「**每张周表的起始日在语义上必须是周一**」作约束反推，对每个候选起始年做全量检验：

| 候选方案 | 127 周中起始日为周一 |
|---|---|
| **最新周 = 2026-09-07** | **124 / 127** |
| 其他所有候选年 | 0 ~ 47 / 127（几乎全错） |

剩下 3 周 `06-15~06-21` / `06-08~06-14` / `06-01~06-07`（第 **1747 / 1776 / 1805** 行）连续相邻，而 2025 年的 `06-16` / `06-09` / `06-02` **全都是周一**——同一段的一处 **off-by-one 笔误**。

**按行号修正后：127 / 127 全部通过，零失败。**（注意：不能用日期做修正键，这三天在文件里出现两组，只有后一组写错。）

已落地为可执行代码并验证：`src/lib/parseHeaders.ts`。
结论：所有事件都能有确定绝对日期，**不需要大面积保留"年份不确定"**。

### 0.2 数据规模（实测，非估计）

| 指标 | 值 |
|---|---|
| 周表 | 127（另 1 张模板） |
| 跨度 | 2023-12-25 ~ 2026-09-07（约 2 年 9 个月，3 个跨年边界） |
| 时刻点 / 非空格 | 1483 / 918（平均每周 7.2 格） |
| 时段 | 早 466 / 中 392 / **晚 59（6%）** |
| 星期 | 周一~周五各 150~184；**周六 64、周日 25** |
| 时间 token | 1482 个，去重 414 |
| **非时间 token** | **1187 个，去重仅 27 个** |

**27 个 token 闭集是本次最重要的工程发现**——它不是"脏到没法解析"，而是可高保真自动解析。品名与剂量都是极小闭集，导入器应做白名单匹配 + 未命中进待认领，而非"半自动、大量人工"。

- 品名：`B6(165)` `B2(104)` `B1(66)` `复合2(68)` `复合(6)` `复合钙(5)` `复合维生素(1)` `复合维生素2(1)` `D3(43)` `维生素D3(4)` `钙d3k2(2)` `鱼油(10)` `鱼油1(6)` `镁(3)` `ps(1)` `E(36)` `A(37)`
- 剂量：`2(506)` `3(68)` `2片(42)` `1(4)` `1片(3)` `2篇(1，错别字)`
- 特殊：`16..07`(行910双点)、`17.06E`(行823时间粘连品名)、`两边`(米诺地尔备注)、`国庆…好转`(唯一效果文本)

### 0.3 关于"品类计数"的陷阱（已纠正两处错误）

- PM 报告称"文件里没有 VE/VA，grep 零命中"。**更正**：字面 `VE`/`VA`/`维生素E`/`维生素A` 确实 0 命中，但真实写法是 **`E A`**（35 次，如 `10.54 E A`）；`10.16 E 10.39 A` 证明 **E、A 是两个独立条目**。品类清单必须补回。
- 简单 grep 品类关键词会**把每个周表的列头也算进去**（128 张表各 1 次）。故"米诺地尔 101 / 二硫化硒 92"是虚高值，真实条目数远小于此（二硫化硒实际仅约 5 格）。

### 0.4 断档（影响统计口径）

12 段断档，最长 **21 天（缺 2 周）**，集中在 2024 年。最大三段：
`2024-04-15→05-06`、`2024-09-16→10-07`、`2026-04-20→05-11`，均为 21 天。

### 0.5 那唯一 1 条效果备注——可以精确对齐（决定性证据）

第 2789 行："国庆期间舌尖下溃疡一直没好，9号晚上吃了之后感觉有明显好转"

主持解析出其所属周表为 **2024-10-07（周一）**，故"9号" = **2024-10-09 周三**。对照该周表格：

```
周三 | 晚 | 22.10 2（维C） | 21.10 2（B复合） | （锌：空）
```

**结论：这条效果备注能精确对齐到具体服用事件**——当天只吃了维C与B复合、没吃锌，且 21:10/22:10 属于仅占 6% 的罕见晚间记录。

这条同时反向验证了年份推断正确（周三对得上），并说明：**"效果↔服用对齐"在这份真实数据上确实成立，不是空想。**

## 1. 团队分歧与主持裁决

### 裁决一：核心价值 = 统计为主，效果关联为附加层（**采纳红队，驳回 PM 核心论断**）

- **PM**：用户说"重在统计"是被现有表格驯化的表达，真实需求是效果关联；主推双向时间轴。
- **红队**：1:1483 最朴素的解释是他**只吃、不观察**。他有 127 次在总结栏写字的机会只写了 1 次——那已是成本最低的场景，他放弃了。PM 把"用户没做"解释成"用户想做但做不到"，是自证。

**裁决：采纳红队。** PM 的洞察有价值（那 1 条确实含量极高，见 0.5），但把它升格为核心、并让首屏挂一条空轨，是拿全部价值去赌一个保持了三年的行为会改变。

**定位：统计为主轴（默认入口），效果记录是附加层，不设独立默认页。** 效果记录能力保留（成本极低），但产品价值必须**在导入当天就成立**，不依赖未来新数据。

### 裁决二：砍掉"双向时间轴 + ±14 天高亮"，改为时间倒序合并流（**采纳红队**）

- **PM/设计师**：双轨 + 点事件高亮前后 14 天。
- **红队**：手机竖屏塞两条轨，收益≈0；且 **14 天对所有品类都是错的**（维C 半衰期小时级，鱼油需 8 周），按品类配窗口则复杂度翻倍。

**裁决：采纳红队。** 改为**时间倒序合并流**：服用记录与效果事件混排，效果事件视觉高亮 + 可搜索。实现成本约十分之一，且在所有屏幕尺寸上都成立。

> 但保留 0.5 的发现：**单条效果事件的"当天吃了什么"必须能一键看到**——这是真实的、已被数据验证的需求，只是不该用双轴实现。做法：点效果事件 → 展示当天（或 ±3 天）的服用清单，简单列表即可。

### 裁决三：依从性分母 —— 用数据自推的"活跃窗口覆盖率"（**采纳红队，修正架构师**）

红队指出硬伤：不做目标/计划，则"依从性 78%"没有基准，数字无意义。架构师用"中位周频次"作分母仍需假设。

**裁决：用数据自推分母，不需要用户承诺任何目标：**
- **活跃周覆盖率** = 有记录的周数 ÷ 期内总周数
- **活跃期周均次数** = 事件总数 ÷ 有记录的周数

于是「维C = 127/127 周、每周 6.9 次」vs「鱼油 = 16 次集中在 3 周」两个数字自己会说话。既给出基准，又不制造负罪感（**明确不做连续打卡天数**）。

### 裁决四：数据真源 = 可导出文件，IndexedDB 仅作缓存（**架构师与红队一致，采纳**）

iOS Safari 对不常访问站点 7 天清数据，浏览器存储**不是长期存储**。故：
- 单一真值 = 用户可见、可导出的文件（JSON，附 Markdown 回灌）
- IndexedDB 只当工作副本
- 导入即提示导出；UI 常驻"复制全部数据"

### 裁决五：技术栈（采纳架构师，但压缩）

Vite + React + TS + Dexie + 手写 SVG + 原生 CSS，纯前端静态 PWA。否决带后端（运维负担 vs 个人自用）、localStorage（容量上限）。
**但压缩**：图表先只做"品类活跃条 + 时段分布"两类，不引入任何图表库。

### 裁决六：导入策略 —— 高保真自动解析 + 可审报告（**修正架构师的"半自动"**）

架构师主张"先生成 staging 让人过一遍再入库"，理由是年份全推断、归并歧义。

**修正**：年份问题**已由 0.1 解决**（127/127 验证通过），不再是主要不确定性。且 0.2 证明 token 闭集仅 27 个。

**故改为：默认自动解析入库，同时强制输出可审的解析报告**（未命中 token 清单、修正清单、随机 20 条原文↔结果抽样对照）。人工只需裁决**极少数未命中项**，而非通读全量。保真度目标 ≥99%，**0 条静默丢弃**。

### 裁决七：E/A 品类补回；外用药纳入模型但默认折叠

- E、A 补回品类清单（见 0.3）。
- 外用药：保留在数据模型中（米诺地尔断续 32 周是"被放弃的方案"的证据），但**默认折叠、不进口服统计**。红队建议"完全不建模等真要记再说"——**不采纳**，因为导入时必须能容纳这两列的数据，否则导入就会丢数据。

## 2. 最终 MVP（最小可用，3 条）

1. **导入 + 解析**：粘贴/读取 `记录.md` → 自动解析为绝对日期事件 → 输出可审报告（未命中清单 + 修正清单 + 抽样对照）。
2. **统计视图**：品类 × 活跃周覆盖率 / 活跃期周均次数 + 时段分布 + 断档提示。**纯表格，默认按月聚合**（窄屏 30 列无需横滚）。导入当天就有价值。
3. **快速补录 + 效果笔记**：任意页可唤起的底部面板，点品类即记（默认当前时间）；一句体感的输入框混入时间倒序流；**一键导出**（JSON + Markdown 回灌）。

**明确不做**：打卡提醒/推送、库存与复购、目标与计划、**连续打卡天数**、任何算法归因/相关系数/p 值、双向时间轴与 ±14 天高亮、社交分享、多用户、云同步、图表库。

## 3. 界面要点（采纳设计师方案，按裁决调整）

- **记录不是 Tab，是任意页可唤起的底部半屏面板**（拇指区）——记录发生在任何时刻，不该要求先切页。
- **15+ 品类的窄屏解法**：按时段历史频次自适应排序的「常吃」芯片行，不做固定分组树、不做搜索（短命品类占比极高，用户不会维护分组）。
- **片数不弹键盘**：点芯片 = 记 1 片立即写入，3 秒内再点累加；撤销走 toast。
- **统计默认按月聚合**，切"周"才 127 列横滚。
- **反误读靠常驻文案而非弹窗**：「只把时间和记录对齐，是否相关由你判断」；标题禁用"有效/改善/导致"。
- **视觉走紧凑数据表感**：低饱和纸感底、单一墨绿强调色、无阴影渐变、数字 `tabular-nums`、深色用暖灰非纯黑（床上用）。

PM 的"90 天内效果事件 ≥15 条"已被裁决一推翻（不再以效果为主轴），且 90 天太长。

## 7. 「复合」歧义已解决（原开放问题关闭）

纪要 v1 曾把「`复合` 四种写法是否同物」列为需用户裁决的唯一实质问题。**复核后发现数据自己已经回答了**，无需用户介入。

### 7.1 证据

| 写法 | 次数 | 周数 | 时段 | **同格伙伴** | 判定 |
|---|---|---|---|---|---|
| `复合2` | 68 | 22 | 仅 2026 | **B2、B6** | 与 B 族并列的独立品（复合B） |
| `复合` | 6 | 3 | 仅 2026 | B2、B6 | 同上，简写 |
| `复合钙` | 5 | 2 | 仅 2026 | **D3** | **不同物**，钙类 |
| `复合维生素` | 1 | 1 | 2026-06-22 | **鱼油、PS** | 多维，语境不同 |
| `复合维生素2` | 1 | 1 | 2026-06-15 | **鱼油** | 同上 |

关键数据：**81 次「复合」家族出现中，74 次与 B2/B6 写在同一个单元格里**，规范形态是 `16.15 B2 2 B6 2 复合2`——即 B2 2片、B6 2片、**复合 2片**，三者并列。

两个孤例原文：
- 行 361：`8.00 复合维生素 2 鱼油1 ps 2`
- 行 403：`复合维生素2 鱼油1`

### 7.2 结论（导入器直接照此实现）

**「复合」不是一种东西的四种写法，而是至少三类不同物：**

1. **`复合` / `复合2` → `bComplex`**（复合B）：与 B2/B6 并列，计入 B 族
2. **`复合钙` → `calciumComplex`**：与 D3 同格，属钙类，**不可并入 B 族**
3. **`复合维生素` / `复合维生素2` → `multivitamin`**：与鱼油/PS 同格，多维

因此 **B 族生命周期统计不会碎片化**——`B1/B2/B6/复合` 归为一组统计，而 `复合钙`、`复合维生素` 必须排除在外。

### 7.3 附带发现

「复合」家族**仅出现在 2026 年**（25 周），2025 年及以前完全不存在。这是用户**近期才开始的写法**，早期 B 族只用 B1/B2/B6 表示。品类演进需按此分段理解。

| E / A | 0（误判不存在） | 37 / 37 | **37 / 37** ✓ |

## 9. 数据已经说出的洞察（产品第一天就该呈现）

这一节回答 MVP 成功标准第 2 条「**导入当天即有价值**」——这些结论**不需要任何新数据**，导入完成就能看到，也是这个产品对用户最有说服力的部分。

**① 你的主干只有三样：维C、B 族、锌。**
其余都是过客。鱼油 16 次、钙 7 次、镁 3 次、PS 1 次——**加起来不到总量的 2%**。三年里真正坚持下来的只有 VC / B1·B2·B6·复合 / 锌。

**② 短命品类呈现清晰规律：都是「试几周就停」。**
鱼油、镁、钙D3K2、PS 全部集中在少数几周内，之后彻底消失。这不是"偶尔忘记记"，是**明确的放弃**——因为如果是漏记，会零散分布而非成簇出现后归零。这个区分只有结构化之后才看得出来。

**③ 你的记录行为有两个强模式：**
- **时段**：早 466 / 中 392 / **晚 59（仅 6%）**——晚间几乎不记，也可能几乎不吃。
- **星期**：周一~周五各 150~184 行，**周六 64、周日 25**——周末断崖式下跌到工作日的 1/6。

这两条合起来说明：**这是一套"工作日白天"的习惯**，周末不在其中。任何提醒或统计若按"每天"假设都会失真。

**④ 有 12 段断档，最长 21 天（缺 2 周）。**
集中在 2024 年（`04-15→05-06`、`09-16→10-07`）与 2026 年（`04-20→05-11`）。**必须在 UI 里显示为"无记录"而非"没吃"**——两者对用户意义完全不同，混为一谈会直接污染所有统计。

**⑤ 唯一一条效果备注，指向一个具体可查的夜晚。**
2024-10-09 周三晚上，你记了 `22.10 维C 2片` + `21.10 B复合 2片`（**没吃锌**），随后写下"舌尖溃疡明显好转"。当晚属于仅占 6% 的罕见晚间服药。
这是三年里**唯一**一次把"吃了什么"和"感觉如何"接上了——产品要做的，就是让这种连接从 1 次变成随手可得。

### 这五条就是产品的"首日价值"

用户打开应用第一眼应该看到的不是空表单，而是：
> 你三年真正坚持的只有 3 样 / 有 8 样试了几周就放弃了 / 你从不在晚上吃、周末基本断档 / 有 12 段空白 / 而你唯一一次记下的效果发生在 2024-10-09 那个晚上。

**这五句话，任何一款现成的健康 App 都给不了——因为只有他有这 127 周的数据。** 这也是这个产品值得做的理由。
