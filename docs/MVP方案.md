# StackIt MVP 方案

> ⚠️ **技术栈已变更（2026-09）**：方案里的 Vite + React + TS 网页应用已废弃，
> 实际交付为 **.NET 8 + WPF 原生 Windows 应用**（代码在 `native/`）。
> 本文档保留为历史方案记录——产品范围与取舍仍然有效，只有技术选型被推翻。

> 一句话定位：**把你 127 周的手写记录，变成一眼能看懂的统计。**
> 桌面应用打开，导入 `记录.md`，立刻看到三年规律；之后随手记、随时导出。
> 版本：v1 · 目标：个人自用、零运维、导入当天就有价值

---

## 1. 范围

### 做（4 件事，构成完整闭环）

| # | 功能 | 用户动作 | 产出 |
|---|---|---|---|
| 1 | **导入解析** | 选文件 / 粘贴 Markdown | 1484 条结构化事件 + 可审报告 |
| 2 | **统计首屏** | 打开就看 | 三年规律（五条洞察，见 §5） |
| 3 | **记一笔** | 点品类即记 | 新事件写入时间流 |
| 4 | **导出** | 一键 | JSON（可重新导入）+ Markdown |

### 不做（明确边界，防蔓延）

- 打卡提醒 / 推送通知
- 库存管理 / 复购提醒
- **目标与计划**、**连续打卡天数**（会制造负罪感，且你从没写过计划）
- 任何算法归因：相关系数、p 值、"洞察推荐"
- 双向时间轴 ±14 天高亮（过度设计，改合并流）
- 账号、云同步、多用户、社交分享
- 图表库（手写 CSS/SVG 即可）

### 分两个交付，先交数据层

| 交付 | 内容 | 为什么先做它 |
|---|---|---|
| **MVP-0** | 解析器 + 解析报告 + JSON 导出（**无 UI**） | 数据可信是前提。先让你确认"没解析错"，再谈界面 |
| **MVP-1** | 统计 / 记录 / 导出 的界面 | 数据对了，UI 只是呈现 |

## 2. 数据模型（最小够用）

```ts
/** 时间：有三种精度，不能一律当成"精确到分钟" */
interface When {
  date: string;              // 'YYYY-MM-DD'（年份已由周一约束确定）
  time: string | null;       // 'HH:mm' | null
  precision: 'minute' | 'day';   // day = 只知哪天（如裸条目 `鱼油1`）
  confidence: 'exact' | 'inferred';  // 仅 3 周笔误修正处为 inferred
  raw: string;               // 永不丢失的原文，如 "16.15 B2 2 B6 2 复合2"
}

interface Item {              // 品类
  id: string;                 // 'vitC' | 'b2' | 'bComplex' | 'minoxidil'
  name: string;               // 显示名
  aliases: string[];          // 别名，只增不删（支持改名不分裂）
  route: 'oral' | 'topical';  // 口服 / 外用（剂量语义不同，须分流）
  group: 'B族'|'维C'|'脂溶性'|'矿物质'|'脂肪酸'|'外用'|'其他';
  unit: string;               // '片'|'粒'|'次'
}

interface IntakeEvent {       // 服用事件
  id: string;
  itemId: string;
  when: When;
  dose: number | null;        // null = 没记片数
  slot: '早'|'中'|'晚'|null;   // 取自行标签，不从时间反推
  source: { line: number; weekStart: string; colHeader: string };  // 可回溯到原文
}

interface Observation {       // 效果/体感事件（与服用平级）
  id: string;
  kind: 'symptom'|'benefit'|'sideEffect'|'note';
  subject: string;            // '舌尖溃疡'
  severity: number | null;    // 0-5，可选
  when: When;
  text?: string;
}
```

**关键设计**：
- `raw` 永存 → 任何解析错误都可回溯、可重跑
- `precision` 显式区分 → 无时间的条目**不参与时段分布统计**，避免污染
- `route` 分流 → 外用（米诺地尔/二硫化硒）默认折叠，**不进口服统计**
- 品类 ID 化 + 别名表 → 改名/合并不会让统计分裂

### 品类清单（已按数据归并，照此实现）

| 归类 | 原文写法 | 备注 |
|---|---|---|
| `vitC` | 维生素C 列 | 主干 |
| `b1` `b2` `b6` | B1 / B2 / B6 | 主干 |
| `bComplex` | `复合` `复合2` | **与 B2/B6 并列**，计入 B 族 |
| `calciumComplex` | `复合钙` | 属钙类，**不并入 B 族** |
| `multivitamin` | `复合维生素` `复合维生素2` | 多维，与鱼油同格 |
| `vitD3` | `D3` `维生素D3` | |
| `calciumD3K2` | `钙d3k2` | |
| `fishOil` | `鱼油` `鱼油1` | 短命 |
| `magnesium` | `镁` | 短命 |
| `ps` | `ps` | 短命（1 次） |
| `vitE` `vitA` | `E` `A` | **全词精确匹配**，禁 `includes`（否则误判） |
| `zinc` | 锌 | 主干 |
| `minoxidil` | 米诺地尔 | 外用 |
| `selenium` | 二硫化硒 | 外用，近乎全空 |

## 3. 功能规格

### 3.1 导入解析（MVP-0）

**输入**：`记录.md`（两种入口都支持）
- 文件选择（`<input type="file">`，手机可从网盘/文件管理选）
- 粘贴全文（手机上更方便，从备忘录复制）

**解析流程**：
```
记录.md → 读周表头 → 定绝对日期 → 逐格切分 → token 匹配 → 事件
                                              ↓ 未命中
                                        待认领清单（不丢弃）
```

**核心规则**（均已实测验证）：
1. **年份**：周表起始日必须为周一 → 127/127 通过；仅第 1747/1776/1805 行按行号修正
2. **列映射**：按表头名，**禁止按列位置**（列数在 4~8 列间漂移）
3. **跳过表头污染**：数据行中「维生素C」字面量应为 0（128 次全在表头）
4. **复合单元格**：以时间 token 为锚点切段，段内最长匹配（品名）+ 剂量
5. **27 个 token 白名单**：未命中一律进待认领，**0 条静默丢弃**
6. **时间夹在中间**：如 `10.16 B6 2 10.43 B2 2`，全局扫锚点，不能只看行首
7. **粘连**：`17.06E` → 1 条 E 事件（全文件唯一，不处理会静默丢失）

**产出**：`staging.json` + 解析报告（浏览器内展示）

### 3.2 统计首屏（默认页）

**默认落在统计页**，不是空记录页——导入当天就要有价值。

三个模块，纯表格/条带，**不引入图表库**：

**① 品类活跃榜**（默认按月聚合，窄屏无需横滚）

**分母必须按「该品类有记录能力的周数」计算**，不能用全 127 周——否则 2026-02 才出现的品类会被永久低估（见 §5.1）。

```
│ 品类      记录周/可记周   周均次数   时段    记录区间          │
│ 维C        127/127       6.9      早·中   2023-12 ~ 至今     │
│ B2         104/127       5.2      早·中   2023-12 ~ 至今     │
│ 锌         ...                                               │
│ D3          11/28        3.9      中     2026-06 ~ 至今 ⚠️   │
│ 鱼油         4/28        5.3      —      2026-06 ~ 2026-07 ⚠️│
│ 镁           1/28        —        —      2026-06 ⚠️          │
│                                                              │
│ ⚠️ = 该品类在 2026-02 前无对应列，早期是否服用不可推断          │
```

- **"可记周"** = 该品类所属列存在的周数（维C/B/锌 = 127；其他维生素列下 = 28）
- **状态只写「记录区间」，禁止写"已停"** —— 无法区分"停用"与"不再记录"
- 短命品类（鱼油/镁/PS）若其最后一次出现**接近该列当前的最后一周**，须标注「可能仍在服用，只是未记录」

**② 行为模式**（两条强规律，数据自己会说话）
```
│ 时段  早 ████████ 466   中 ██████ 392   晚 █ 59 (6%)  │
│ 星期  一~五 ████ 150-184   六 ██ 64   日 █ 25         │
```

**③ 断档提示**
```
│ 12 段无记录，最长 21 天                                │
│ 2024-04-15 → 05-06 (21天)                            │
│ 2024-09-16 → 10-07 (21天)                            │
│ 2026-04-20 → 05-11 (21天)                            │
```
**必须显示"无记录"而非"没吃"** —— 两者意义完全不同。

### 3.3 记一笔

**不是 Tab，是任意页可唤起的底部半屏面板**（拇指区）。

```
┌────────────────────────────────┐ ← 375px, 60vh
│  10:54  周一 · 今天    [改时间] │
│  [早] [中] [晚]                 │
├────────────────────────────────┤
│  常吃（按时段自动排序）          │
│  ┌────┐┌─────┐┌───┐            │
│  │维C ││B复合││锌 │  点=记1片   │
│  └────┘└─────┘└───┘  再点=×2   │
│  ┌────┐┌─────┐┌───┐            │
│  │D3  ││鱼油 ││E  │            │
│  ▸ 外用药（2，默认收起）         │
├────────────────────────────────┤
│  已记 维C×1        [撤销]  [完成]│
└────────────────────────────────┘
```

- **时间**：默认当前，点开才改（90% 场景不碰）
- **片数**：点 = 记 1 片立即写入，3 秒内再点累加；**不弹键盘**
- **排序**：按时段历史频次自适应，不做分组树/搜索（短命品类多，你不会维护分组）
- **撤销**：toast 3 秒

### 3.4 效果笔记（附加层）

一个输入框混入**时间倒序合并流**，效果事件视觉高亮 + 可搜索。

点效果事件 → 看**当天**吃了什么（简单列表，不是双轴）。

反误读靠**常驻文案而非弹窗**：
> 标题「这段时间我在吃什么」· 禁用"有效/改善/导致"
> 常驻灰字：「只把时间和记录对齐，是否相关由你判断」

不输出任何相关系数 / p 值——给数字会让人误以为做过检验。

### 3.5 导出（数据主权）

- **JSON**：完整备份，可重新导入（往返无损）
- **Markdown**：回灌成原表格格式，人类可读

**数据真源是导出文件，浏览器存储只是缓存**（iOS Safari 7 天会清）。故：
- 导入即提示导出
- 常驻「复制全部数据」入口

## 4. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | **Vite + React + TS** | 统计口径容错低，TS 防 `precision` 被误用 |
| 存储 | **localStorage**（MVP） | 1484 条约 300KB，远低于 5-10MB 上限；Dexie 暂不需要 |
| 图表 | **手写 CSS 条 + SVG** | 只需条带/矩阵两类，引库多 400KB |
| 样式 | 原生 CSS 变量 | 无构建负担 |

**取舍说明**：
- 不用 Dexie —— 真源是导出文件，IndexedDB 的容量优势用不上；数据量增长后再上
- 不用后端 —— 个人自用，运维负担 vs 收益不成比例
- 视觉：紧凑数据表感（低饱和纸感底 + 单一墨绿强调色 + 无阴影渐变），深色用暖灰非纯黑（床上用）

## 5. 首日价值（打开就该看到）

这五条**不需要任何新数据**，导入完成即可呈现，也是产品最不可替代的部分：

1. **你的主干只有 3 样**：维C、B 族（B1/B2/B6/复合）、锌——三年不断
2. **从不在晚上吃**（6%）、**周末基本断档**（周日 25 行 vs 工作日 150~184）
3. **有 12 段空白**，最长 21 天
4. **唯一一次效果记录**发生在 **2024-10-09 晚**：22:10 维C + 21:10 B复合（没吃锌）→ 溃疡好转
5. **你的表格本身在进化**：列数从 3 列长到 6 列，2026-02 新增「其他维生素」列后，才开始记录 D3/鱼油/钙/镁/E/A

> 这几句，任何现成健康 App 都给不了，因为只有你有这 127 周数据。

## 5.1 ⚠️ 关键修正：不要说"你放弃了某些品类"

**这是一个会导致错误结论的陷阱，MVP 必须规避。**

早期分析（包括本方案 v1 和团队各成员报告）都说"鱼油、镁、钙D3K2、PS 是试几周就停的短命品类"。**这个结论是错的。**

**真相**：表格结构随时间**扩展**，不是收缩（文件倒序导致所有人都看反了）：

| 起始 | 列数 | 结构 |
|---|---|---|
| 2023-12-25 | **3 列** | 维C / B复合 / 锌 |
| 2024-08-12 | 4 列 | +米诺地尔 |
| 2024-11-04 | 5 列 | +二硫化硒 |
| **2026-02-02** | **6 列** | **+其他维生素** |

实跑验证：D3 / 鱼油 / 镁 / PS / 钙d3k2 / E / A 的记录**共 74 次，100% 落在「其他维生素」列，无一例外**；且 **2026-02-02 该列出现之前，这类记录为 0 条**。

**所以这些品类不是"你停了"，而是此前表格里没有列可以记它们。** 两者含义完全相反：
- "试几周就停" → 你试过、放弃了 → 结论：别再买了
- "此前无列可记" → 可能一直在吃，只是没记 → 结论：**数据缺失，不可推断**

**对 MVP 的三条硬要求**：

1. **禁止**把"最后一次出现"当作停用日期。品类生命周期只能标注「**记录区间**」，不能标注「服用区间」。
2. 对 2026-02 之前**不存在**的列，统计须显式标注「**该时段无此列的记录**」，而非 0。
3. 断档与"品类消失"必须在 UI 里**区分呈现**：前者是"没记"，后者是"列都没有"。

这条修正直接影响 §3.2 品类活跃榜的分母口径，也是本方案与" naive 统计"的根本区别。。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 浏览器数据被清空（iOS 7 天） | 文件为真源，常驻导出入口，导入即提示导出 |
| 解析静默错误污染统计 | 27 token 白名单 + 未命中进报告 + 抽样对照 |
| 品类改名导致统计分裂 | ID 化 + 别名表（只增不删），合并可撤销 |
| 把"同期"读成"因果" | 组件级禁词 + 常驻免责，**不输出任何统计量** |
| 你中途放弃记录 | 产品任何时刻停下都完整——价值在导入当天兑现 |
