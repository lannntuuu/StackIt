# StackIt 移动网页设计方案（产品设计师 · v1）

## 1 信息架构

```
            ┌────────────────────────────┐
            │   三个主 Tab，默认「统计」     │
            └────────────────────────────┘
    记录 ◂─────────┬──────────┬─────────► 关联
   （半屏速记面板）   统计(默认)    效果事件 ↔ 服用
          └──── 底部常驻「记一笔」胶囊 ────┘
                 （任意 Tab 都能唤起记录）
```

- **记录**：不是一个 Tab 页，而是**底部半屏面板（bottom sheet）**，任意 Tab 都能唤起——记录发生在任何时刻，不该要求先切页。
- **统计**：默认落地页。理由：核心价值是统计，且历史导入后"一打开就见三年趋势"必须兑现。
- **关联**：效果事件轨 + 服用轨对齐。
- **设置**：统计页右上角 ⚙。v1 只放三件事：品类改名、外用药折叠开关、导出 JSON。

## 2 记录面板（最高频）

**解法：时段自适应排序 + 动态"常吃"行。不做固定分组树，不做搜索。**

理由：15+ 品类里三年不断的只有 VC/B 族/锌，鱼油(16)、镁(3)、PS(1) 都是短命品类。按时段历史频次排序，早上打开就先看到早上最常吃的，回答的是"此刻我要吃什么"而不是"系统里有什么"。固定分组需要用户维护，而他连计划都没写过，必然不维护。搜索在 15 个品类里比滚动慢。

- **时间**：默认当前时间（大号 `10:54 周一 · 今天`），点开才能改时段（早/中/晚）+ 时间 + 日期（默认今天）。90% 场景不用碰——记录都发生在当下。晚间格子仅 59 个，晚间打开时列表自动只排晚间出现过的品类，不摆无效项。
- **片数**：默认 1。**点一下 chip = 记 1 片，立即写入**；3 秒内再点同一 chip 累加（右上角浮 `×2`）。>1 片是少数，用弹键盘输入是过度设计。
- **外用药**：折叠为一行 `▸ 外用药（2）`，展开后同上，不进主视图。
- 底部常驻「本次已记 VC×1 B复合×1 [撤销]」。

```
┌────────────────────────────────────┐ ← 375px，底部半屏 60vh
│  10:54  周一 · 今天                  │ 56px 时间条（点开改）
│  [ 早 ] [ 中 ] [ 晚 ]      [改时间]   │
├────────────────────────────────────┤
│  常吃（近 14 天自动排序）              │ 11px 标签
│  ┌────┐ ┌────┐ ┌────┐               │ chip 44px 高 / ≥64 宽
│  │ VC │ │B复合│ │ 锌 │               │ 点=记1片，再点=×2
│  └────┘ └────┘ └───×2┘              │ ← 角标
│  ┌────┐ ┌────┐ ┌────┐               │
│  │ D3 │ │鱼油 │ │ 钙 │               │
│  └────┘ └────┘ └────┘               │
├────────────────────────────────────┤
│  这个时段还吃过          口服 6 种     │
│  [ B1 ][ B2 ][ B6 ][ 镁 ][ E ][ A ] │ 单行横向滚动
│  ▸ 外用药（2，默认收起）               │
├────────────────────────────────────┤ 56px + safe-area
│  已记 VC×1  B复合×1         [ 撤销 ]  │
└────────────────────────────────────┘
```

## 3 统计页（核心价值）

顶部：区间（全部 3 年 / 1 年 / 3 月）+ 粒度（月 / 周）。两个视图是页内次级切换，不新增 Tab。

**视图 A 品类榜（默认）**——一行一品类，行高 44px，15 行约两屏。列：名称 / 三年条带 / 覆盖率 / 起止。**按覆盖率降序**，直接回答"哪个吃得最规律""哪个是短命品类"。

**视图 B 热力矩阵**——纵轴品类（口服在上，外用收起），横轴时间。**默认按月**：30 列 × 6px ≈ 200px，窄屏无需横向滚动；切"周"才是 127 列并横向滚动。深浅 = 该月有记录天数占比，无记录留白——"表头从 8 列收缩到 3 列"和断档一眼可见。

底部「断档」区：列出 >14 天的空白区间，回答"什么时候断的"。

## 4 效果关联页

上半事件轨 → 点事件 → 下半自动对齐该日期 **±14 天**，窗口外用淡灰遮罩，窗口内留白；再按品类列出窗口内每天的有/无记录点。软件只做对齐，判断权留给人。

**反误读文案（关键，四条都要落地）**
1. 页头标题：**「这段时间我在吃什么」**。禁用"影响 / 归因 / 有效 / 改善"。
2. 事件卡下常驻一行 11px 灰字：**「只把时间和记录对齐，是否相关由你判断」**——常驻文字，不是弹窗、不用关闭、不阻断。
3. 窗口标题写 `2025-09-25 ~ 10-23 前后 14 天的记录`，**不写**"溃疡好转期间"。
4. 严重度改称**「体感强度：强 / 中 / 轻」**，事件录入占位用模板 `部位 + 变化`（舌尖溃疡 · 好转/加重/新出现），避免医疗暗示。

## 5 移动端交互细节

- 底部 Tab 56px + safe-area；「记一笔」胶囊居中悬浮于 Tab 上方，落在拇指区。
- 记录面板 60vh：时间条在顶（视线），品类 chip 在下半（拇指）。
- **误触与撤销**：点即写 + 3 秒撤销 toast；写入不触发统计页重排跳动。
- **空状态**：某时段无历史 → 该区提示"这个时段还没记过"；全局空数据只在首次出现一次引导页。

## 6 视觉方向

**紧凑数据表感，不是轻松打卡感。**
理由：跨度 2 年 9 个月 × 15 品类，这是来读趋势的工具；大圆角大卡片 + 渐变 + 笑脸会稀释信息密度，且每天打开更易疲劳。低饱和、高密度、安静的界面才耐看三年。

- 纸感浅底 `#FBFAF8`，正文 `#1A1A1A`，1px `#E6E4DF` 描边，**无阴影无渐变无圆角超过 8px**。
- 单一强调色墨绿 `#2F6B4F`；口服 = 绿系明度阶，外用 = 琥珀系（天然区分且默认折叠）。
- 数字 `tabular-nums`；字号 11/13/15/17 四级；行高 44px（≥ 触摸目标）。
- 深色模式用 `#16171A` 暖灰底，非纯黑（床上用）。

## 7 明确不做（防过度设计）

提醒/推送、库存、复购提醒、目标与计划、**连续打卡天数**、任何算法归因或"相关度评分"、社交/分享、图表动画、v1 的云同步与 PDF 导出、品类自定义分组树、搜索框（15 个品类不需要）、录入表单与确认弹窗。
