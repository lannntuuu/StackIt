# 记一笔 · 重设计方案（v2）

> 背景：桌面端（.NET 8 + WPF）的「记一笔」弹层（`native/StackIt.App/Views/RecordSheet.cs`）
> 用起来很别扭。本文先定位**为什么难用**（每条都对着代码），再给一套回到原 MVP 初衷、
> 又适配桌面交互的新方案。原产品方案见 `docs/MVP方案.md` §3.3、`design/设计方案.md` §2。

> **关于第 1 节的代码行号**：那一节是对**改造前**旧实现的取证，指向的
> `OpenDose` / `DoseBar` / 搜索框 / `RedrawFooter` 等代码**早已删除**，行号随之失效。
> 留着是为了保留"当初为什么改"的依据，**不要拿它当当前代码的索引**；
> 要读现状请看 `RecordSheet.cs` 本身。
>
> **§3.3 / §3.4 / §5 的写入与撤销语义在 2.0.3 有过一次推翻**（"改时间/改日期要真的落盘"）：
> 原文写的是"不动已记内容"，那正是"改了时间关掉又变回去"的成因。改动原因与断言见

## 1. 现状与问题（对着代码）

### 1.1 交互模型偏离了原设计
原 MVP 定的是「**点一下 = 记 1 份，立即写入；再点 = ×2；不弹键盘、不做搜索框**」
（`docs/MVP方案.md` §3.3、`design/设计方案.md` §7 明确不做的清单含「搜索框」）。
现在实现全部反着来：

| 原设计 | 现状实现 | 位置 |
|---|---|---|
| 不弹键盘、点 chip 即写 | 点品名 → 开**二级数量面板**（`OpenDose`/`DoseBar`），再点数字或确认 | `RecordSheet.cs:544-651` |
| 不做搜索框（15 个品类不需要） | 擅自加了常驻搜索框，每次 `TextChanged` 整树重绘 | `RecordSheet.cs:445-516` |
| 点格子 = 记 1，再点累加 | 点格子确实 +1，但语义是「再建一条」 | `RecordSheet.cs:737-758` |

### 1.2 真实的数据 bug：累加被拆成多条记录
`Pick(itemId, s, 1)` 每次调用都 `AddEvent` 一条 `dose=1` 的新事件
（`RecordSheet.cs:752`）。连续点同一格两次 = **两条 `dose=1`**，而不是一条 `dose=2`。
而 `RecordSheet.cs:729-736` 的注释明说「一律写成一条 `dose=N`，不要 N 条 `dose=1`」——
**代码和自己的设计意图矛盾**。后果：统计里的「次数」被虚高，和「用户心里的次数」偏差
一路渗进格子视图（虽 `DosesOfDay` 求和显示成 2，底层却是碎片）。

### 1.3 布局难扫读
16 个口服品类被铺成「品类 × 时段」网格：名字列 112px + 3 个时段列
（`RecordSheet.cs:302-389`）。展开「全部品类」后是一堵高墙，既不按「此刻我要吃什么」
排序，也不像原设计的「常吃 chip 行」。`startup-error.log` 中 3 次崩溃
（`2026-10-13`）都发生在点击格子 → `RedrawFooter` 的路径上，说明这条高频路径不稳。

### 1.4 架构脆弱
整个弹层没有视图模型，任何改动（点格子、切时段、打字、撤销）都 `Render()` **拆掉并重建整棵可视树**
（`RecordSheet.cs:263-280`），于是要额外加：
- `_rendering` 重入锁，挡住搜索框构造时触发的 `TextChanged` 重入；
- `Dispatcher.BeginInvoke` 把焦点「抢回」搜索框（`RecordSheet.cs:499-507`）。

这堆补丁本身就是「不该整树重绘」的证据。底部条在滚动区外，还得单独 `RedrawFooter`
（`RecordSheet.cs:786-792`），旧版正是在这里崩的。

### 1.5 时间编辑反人类
改时间是一个裸 `TextBox` + 手动解析（`TryParseTime`，`RecordSheet.cs:217-240, 853-863`），
要自己敲 `HH:mm`，没有步进、没有掩码。补记过去某天靠 `DatePicker` + 「今天」按钮，路径深。

## 2. 设计目标

1. **一条主路径 0  friction**：打开 → 点品类 → 已记。默认就是「现在 / 今天 / 自动时段」。
2. **累加归并到同一条记录**：同一 (品类, 日期, 时段) 反复点 = 同一个事件 `dose+1`，不再是碎片。
3. **回到「常吃优先」**：按「当前时段的历史频次」排 chip，回答「此刻吃什么」，而不是列全表。
4. **砍掉二级弹层和搜索框**：数量用 chip 上的内联步进器解决；16 个品类不需要搜索。
5. **架构换成「局部更新」**：绑一个轻量 VM，只动被改的控件，去掉 `_rendering`/`BeginInvoke` 补丁。

---

## 3. 新交互模型

### 3.1 核心控件：品类步进器（明确不做「点格子 +1」）
每个口服品类是一行「步进器」（参考 Apple 健康 / Medisafe / MyTherapy 的补剂、用药计数）：
名称在左，右侧永远并排 `[−] N [＋]`，两个按钮**一样大、一样显眼**，始终可见。

- **未记（N=0）**：整行变灰，`−` 禁用（已 0 不能再减），`＋` 仍可点。
- **点 `＋`**：记 1 份到「当前时段/当前时间」，立即写入，N+1。
- **点 `−`**：直接减 1，改同一条记录的 `dose`；减到 0 就删整条。

> 不再有「点格子加 1 / 再点打卡」这类隐式语义——加减都是显式按钮，
> 用户要「直接 −1」时一眼就能找到、点一下就减，不用去猜隐藏的减号。
> 这也贴合药品/补剂类 App 的通行做法：一排项目，每项旁边有独立的 −/＋。

### 3.2 常吃排序（回到原设计意图）
用 `HistoryCalc.RecentItems(db, slot: 当前时段, limit: 8)`（或新增按时段取 Top8 的口径）
排「常吃」行；其余口服品类收进「全部口服 ▸」折叠区。外用单独一行、默认折叠（沿用原规则）。
**不设搜索框**——16 个品类滚动/折叠足够，搜索反而多一步。

### 3.3 时间/时段
- 顶栏大号：`现在 14:32 周二 · 今天`。默认即此刻，90% 场景不碰。
- 「改时间」是一个**内联展开**的小条：日期（限制 ≤ 今天，选未来直接弹回）、
  时间（带 ↑↓ 步进的 `TextBox` 或 `TimePicker` 风格，不再裸解析）、时段（早/中/晚三选一，默认由时间推导）。
- **改时间 / 改日期要真的落盘**（2.0.3 起，本节原文写的是"不动已记内容"，已推翻）：

  改时间是"我刚记的这笔其实发生在别处"，不是"改写今天的所有记录"。所以提交时
  （按回车 / 失焦）把**本次弹层里经手过的记录**（`RecordSheet._session`）一起重定时：

  | 改什么 | 之前（错的） | 现在 |
  |---|---|---|
  | 时间 | 只改界面上的 `_time`，不写入 | 经手的记录 `When.Time` 换成新值，时段按新时间重算 |
  | 日期 | 只改 `_date` 再 `PourDay()`，记录留在旧日期 | 经手的记录 `When.Date` 一起搬过去 |
  | 时段 | 只影响高亮与「常吃」排序 | 由时间推导，写进记录；`Slot` 跟着改 |

  边界是 **`_session` 里只收本次打开后记下/改过的 id**。打开时就存在的历史记录一律不碰
  —— 否则"补记昨天的维生素"会顺带把昨天所有记录洗一遍。

  必须落盘的理由：只改界面的话，大字从 `09:00` 变成 `17:20` 看着像生效了，
  关掉弹层再看还是 `09:00`，用户感受到的就是"改了没保存"。加一个「保存」按钮也解决不了：
  真正缺的是"把这笔已记的记录一起挪过去"这个动作，不是缺一次点击。

- 切时段（点早/中/晚 tab）仍**只改高亮和「常吃」排序**，不动已记内容 ——
  这是"我想按哪个时段浏览"，与上面"这笔其实发生在别处"不是一件事，别混。

### 3.4 本次已记 + 撤销
底部常驻：`已记 维C×1 B复合×2 锌×1   [撤销]`。

「撤销」按 `_undo` 栈逐步回退**最后一步**操作。原文写的「沿用现有 `_added` 列表」已过时：
`_added` 只记 id，撤销只会把 `dose` 减 1，改过时间就退不回去。现在每一步存的是
`UndoStep { Id, ItemId, Dose, When, Slot, Created, Removed }` —— **改动前的副本**：

| 这一步做了什么 | 撤销做什么 |
|---|---|
| 新建了一条 | 整条删掉 |
| 改了 dose / 时间 / 时段 | 把 `dose`、`When`、`Slot` 一起写回改动前的值 |
| 减到 0（整条被删） | 按原样重新建回来 |
| 改时间触发的重定时 | 时间与时段一起退回 |

`When` 必须存**副本**：库里那条是活动引用，`Store.UpdateEvent` 会就地换掉它的 `When`，
存引用等于没存（这一条踩过，自检里有一条断言专门守着）。

## 5. 数据层改动（最小、必要）

1. **同记录归并**：弹层内维护 `Dictionary<(itemId, slot), eventId>` 的「本会话该格对应的事件」。
   - 该格还没有事件 → `AddEvent`（dose=1）。
   - 已有 → `UpdateEvent(id, dose: +1 / -1)`，**不再新建**。
   - 这直接修复 §1.2 的碎片 bug，并兑现旧版注释里「一律写成一条 `dose=N`」的意图
     （现在落实在 `RecordSheet.Tap`）。
2. **复用现有 `Store.UpdateEvent`**（`Store.cs`），无需新存储能力。

   ⚠ 它的覆写语义不对称，调用方必须知道：`Dose` / `Slot` 是**无条件覆写**，
   而 `When` 是 `if (when is not null)`。所以：

   - 改 time / slot 时**必须把 `when` 一起传**，否则时间悄悄留在旧值上
     （2.0.3 前 `Tap` 就传了 `null`，这是"改了时间没保存"的成因之一）；
   - 不改的那一项要按记录现值交出去，随手传 `null` 会把它洗掉。

   界面上另有一条：`Tap` 写入前先 `CommitPendingTime()`（时间框只在 `LostFocus` /
   回车提交，敲完直接点 ＋ 会漏），且 `slot` 要重新取 `_slot` 而不是用入参 ——
   提交可能已经把时段从「早」推到「晚」。
3. **重定时**：改时间/日期调 `RetimeSession()`，按 `_session` 把经手的记录重写
   （见 §3.3）。它同时把每次重定时压进 `_undo`，所以撤销能退回改之前。
4. **撤销**：只走 `_undo` 栈，语义见 §3.4。dose 归零时 `RemoveEvent`；
   撤销"减到 0"那一档则 `AddEvent` 重建。

## 6. 架构简化（去掉脆弱补丁）

- 引入一个极小的 `SheetVm`：`SelectedDate / SelectedSlot / SelectedTime / 各 (item,slot) 的 count`。
- chip、底部条**绑定**到 VM；只有被改的那个控件更新自身（count 文本、步进器显隐），
  不再 `Render()` 整树。
- 删除 `_rendering` 重入锁、`RestoreFocusToQuery`、`FindBoxes` 遍历抢焦点等补丁
  （`RecordSheet.cs:263-280, 492-539`）。搜索框已砍，这些补丁失去存在理由。
- `RedrawFooter` 不再需要（`RecordSheet.cs:786-792`）——底部条随 VM 局部更新。

## 7. 键盘 / 快捷键（桌面增益，不强制）

- `1`~`8`：给「常吃」第 N 项 `＋1`（相当于点它的 ＋ 键）。
- `↑`/`↓` 或 `Ctrl+↑/↓`：在展开的时间条里步进分钟/小时。
- `Esc`：关闭；`Ctrl+Z`：撤销最后一条。
- 全局热键（可选，独立于本弹层）：托盘/主窗口监听，一键唤起「记一笔」。

---

## 8. 明确不做（防过度设计）

- **搜索框**（16 个品类不需要，且与原设计冲突）。
- **二级数量弹层**（用内联步进器替代）。
- **打卡/提醒/连续天数**（沿用全局边界，见 `docs/MVP方案.md` §1）。
- **拖拽排序、自定义分组树**（用户从不维护分组）。
- **图表动画、归因评分**（全局不做）。

## 9. 验收标准（可测）

```
✓ 打开到写入 ≤ 2 次点击（点该项的 ＋ 即记 1 份），默认即现在/今天/自动时段
✓ 同一 (品类, 日期, 时段) 连点 ＋ N 次 = 库里 1 条记录、dose=N（非 N 条 dose=1）
✓ 步进器 − 始终可见、可直接减 1，改的是同一条记录 dose，归零删整条、不产生新事件
✓ 无搜索框；常吃按当前时段频次排序；外用默认折叠
✓ 时间编辑带步进，选未来日期被弹回今天
✓ 删除 _rendering / RestoreFocusToQuery / RedrawFooter 等补丁，无回归
✓ 连点 20 次不同/相同 ＋，底部条与底层 db.json 一致，无异常（覆盖 startup-error.log 的崩溃路径）
✓ 撤销可回退「新增」「步进器加减」「改时间/改日期」，且 db 同步
✓ 快捷键 1~8 给常吃项 +1、Ctrl+Z 撤销生效
✓ **改时间落盘**：记一笔 → 改时间 → 按 Enter → 关掉弹层 → 重新读磁盘，那条记录是新时间
✓ **改日期落盘**：同上，记录的 date 搬到新日期（而不是从界面上"消失"）
✓ **时段跟随**：改成 17:20 时记录 slot 变「晚」，统计按 slot 汇总不错位
✓ **不误伤历史**：打开时就存在的记录，改时间后保持原样
✓ **撤销退得回时间**：改完时间一直撤销，能回到改之前的 time / slot
```

> 最后五条是 2.0.3 补的，对应 `--sheet-test` 里那 5 条断言。它们各自都做过反证：
> 把 `RetimeSession` 改成空转，五条同时变红 —— 症状正是用户报的「改了时间关掉又变回去」。

## 10. 与现有方案的差异说明

本方案**不是推翻 MVP**，而是把它在桌面端跑偏的部分拉回正轨：

- 原 MVP 要「点一下记 1、不弹键盘」→ 现状用二级面板违背了，本方案用内联步进器兑现。
- 原 MVP 要「不做搜索框」→ 现状加了，本方案砍掉。
- 原 MVP 要「常吃按时段频次排序」→ 现状铺成固定网格，本方案恢复 chip 行。
- 原 `RecordSheet` 自己承诺「一条 dose=N」却写出碎片 → 本方案从数据层根治。

视觉仍沿用全局语言（纸感底、单一墨绿强调、`tabular-nums`、44px 触摸目标，见
